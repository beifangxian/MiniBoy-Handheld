## 1. ESP-IDF 工程结构

### 相关文件

- `CMakeLists.txt`：定义 ESP-IDF 工程。
- `base.cmake`：引入 ESP-IDF 工程并配置共享构建逻辑。
- `sdkconfig`：保存 ESP-IDF 和芯片配置。
- `idf.py`：ESP-IDF 官方构建、配置、烧录和监视工具。
- `rg_tool.py`：本项目的多应用构建和烧录工具。

本项目不是一个单独的 ESP-IDF 应用，而是由多个独立应用共同组成一份固件镜像。

## 3. ESP32 应用分区和启动流程

每个应用会被编译成独立的 ESP32 App，并放入固件镜像中的应用分区。

启动器通过应用分区名称启动其他应用，应用之间不是普通函数调用关系。

### 应用切换流程

1. 用户在启动器中选择 ROM。
2. 启动器保存目标分区、系统名称和 ROM 路径。
3. 调用 `rg_system_switch_app()`。
4. ESP32 重启。
5. 目标应用读取启动参数。
6. 进入对应模拟器或阅读器主循环。

### 关键文件

- `launcher/main/applications.c`：注册 ROM 类型和对应应用。
- `components/retro-go/rg_system.c`：保存启动参数、切换应用和系统重启。
- `retro-core/main/main.c`：根据配置分派到不同模拟器入口。

## 5. 硬件接口知识

### SPI

SPI 用于连接屏幕和 SD 卡。

- 屏幕使用 `SPI2_HOST`。
- SD 卡使用 `SPI3_HOST`。
- 屏幕底层驱动：`components/retro-go/drivers/display/ili9341.h`
- 屏幕管理：`components/retro-go/rg_display.c`
- SD 卡和文件系统：`components/retro-go/rg_storage.c`

### I2S

I2S 用于向外部音频设备输出数字音频。

- 音频管理：`components/retro-go/rg_audio.c`
- I2S 驱动：`components/retro-go/drivers/audio/i2s.c`
- 当前使用外部 DAC 配置。

### GPIO

GPIO 用于按键、屏幕控制信号、背光和复位。

- 按键处理：`components/retro-go/rg_input.c`
- GPIO 映射：`components/retro-go/targets/t320-s3/config.h`
- 当前按键为低电平有效，并启用内部上拉。

### ADC

ADC 用于读取电池电压。

- 读取和换算：`components/retro-go/rg_input.c`
- ADC 配置：`components/retro-go/targets/t320-s3/config.h`
- 电池检测引脚：GPIO4。

### RMT

RMT 用于精确输出 WS2812 灯珠所需的时序信号。

- WS2812 驱动：`components/retro-go/drivers/led/ws2812.c`
- LED 配置：`components/retro-go/targets/t320-s3/config.h`

## 6. 驱动和公共抽象层

应用一般不直接操作 GPIO，而是通过 Retro-Go 公共接口使用硬件。

| 功能 | 实现位置 |
|---|---|
| 系统初始化、应用切换和硬件初始化 | `components/retro-go/rg_system.c` |
| 显示、旋转、缩放和刷新 | `components/retro-go/rg_display.c` |
| Surface 和像素缓冲 | `components/retro-go/rg_surface.c` |
| 按键和电池检测 | `components/retro-go/rg_input.c` |
| 音频设备选择、音量和滤波 | `components/retro-go/rg_audio.c` |
| SD 卡和文件系统 | `components/retro-go/rg_storage.c` |
| GUI、菜单和对话框 | `components/retro-go/rg_gui.c` |
| 设置和持久化配置 | `components/retro-go/rg_settings.c` |
| 具体显示、音频和 LED 驱动 | `components/retro-go/drivers/` |

修改硬件时，通常先修改 `targets/t320-s3/config.h` 中的 GPIO 和功能宏；只有通信协议或驱动行为改变时，才需要修改 `drivers` 或对应的 `rg_*.c` 文件。

## 7. CMake 和编译宏

### 构建入口

- 根目录各应用的 `CMakeLists.txt` 定义应用工程。
- `base.cmake` 提供共享构建逻辑。
- `components/retro-go/CMakeLists.txt` 注册公共组件、库和编译选项。

### 重要编译宏

- `RG_BUILD_TARGET`：硬件目标，例如 `RG_TARGET_T320_S3`。
- `RG_PROJECT_APP`：当前编译的应用名称。
- `RG_PROJECT_VER`：项目版本。
- `RG_ENABLE_NETWORKING`：是否启用网络功能。
- `RG_ENABLE_PROFILING`：是否启用性能分析。
- `RG_BUILD_RELEASE`：是否使用发布构建配置。

`rg_tool.py` 会在调用 ESP-IDF 前自动注入这些宏。

## 9. 固件编译流程

在 ESP-IDF Terminal 中，从仓库根目录执行：

```bat
python rg_tool.py --target=t320-s3 build-img
```

执行过程大致为：

1. 设置 `IDF_TARGET=esp32s3`。
2. 读取 `t320-s3/env.py` 和 `t320-s3/sdkconfig`。
3. 依次编译六个应用。
4. 生成各应用的 `.bin` 文件。
5. 生成 Bootloader。
6. 使用 `tools/mkfw.py` 打包完整 `.img` 镜像。

输出文件：

```text
retro-go_chaeng_t320-s3.img
```

干净重编译：

```bat
python rg_tool.py --target=t320-s3 release
```

## 10. 固件烧录流程

编译并直接烧录完整镜像：

```bat
python rg_tool.py --target=t320-s3 --port=COM3 install
```

将 `COM3` 替换为实际串口号。

也可以手动使用 `esptool.py`：

```bat
esptool.py --chip esp32s3 --port COM3 write_flash --flash_size detect 0x0 retro-go_chaeng_t320-s3.img
```

烧录前需要：

- 安装 ESP-IDF 5.5.5。
- 激活 ESP-IDF Terminal 环境。
- 确认 `IDF_PATH` 已设置。
- 安装 USB 串口驱动。
- 确认设备串口号。
- 必要时按住 BOOT 键并按 RESET 进入下载模式。

## 11. 串口监视和单应用调试

单独烧录某个应用：

```bat
python rg_tool.py --target=t320-s3 --port=COM3 flash prboom-go
```

查看应用日志：

```bat
python rg_tool.py --target=t320-s3 --port=COM3 monitor prboom-go
```

烧录后自动监视：

```bat
python rg_tool.py --target=t320-s3 --port=COM3 run prboom-go
```

## 12. 主题、字体和翻译

### 主题和图片

启动器图片位于 `themes/default/`。修改图片后运行：

```bat
python tools/gen_images.py
```

生成的 C 文件位于 `launcher/main/images.c`。

### 字体

- UI 使用 `components/retro-go/fonts/` 中的字体资源。
- TXT 阅读器使用 `txt-reader/main/` 中的多字号字体资源。
- 中文文本依赖 GBK/Unicode 对照表和 UTF-8 文件系统支持。

### 翻译

- 翻译定义：`components/retro-go/translations.h`
- 本地化实现：`components/retro-go/rg_localization.c`
- 新增界面字符串时使用 `_(...)` 宏。
- 可使用 `tools/rg_locate_str.py` 查找缺失翻译。

## 13. 当前项目限制记录

以下是项目当前已有的结构特点，暂不代表本清单会自动修复这些问题：

- `rg_tool.py` 默认目标仍为 `odroid-go`，本项目编译时必须显式指定 `--target=t320-s3`。
- 应用分区大小在 `rg_tool.py` 中固定定义，应用或字体变大时要检查空间。
- 构建脚本会生成临时 `partitions.csv`。
- 启动器注册的系统数量可能多于实际构建的应用数量。
- GPIO0 同时承担启动/恢复相关功能和按键功能，具体行为依赖硬件设计。
- 网络更新配置包含跳过 TLS 证书验证的选项。
- 应用切换依赖保存启动参数和整机重启。
