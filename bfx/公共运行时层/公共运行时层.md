# 公共运行时层

## 层级职责

公共运行时层是所有应用共享的平台能力，负责统一处理：

- 系统生命周期和应用分区切换
- 显示、Surface、帧缓冲和 GUI
- 输入、按键和电池 ADC
- 音频设备、音量和音频队列
- SD 卡、FATFS、ROM、存档和资源
- NVS 设置、本地化和网络服务

应用通过这一层提供的 `rg_*` 接口工作，避免每个应用重复实现硬件和系统逻辑。

## 模块入口

| 模块 | 文件 | 主要职责 |
|---|---|---|
| 系统 | [`rg_system.c/.h`](../../components/retro-go/rg_system.c) | 初始化、启动参数、应用切换、重启和退出 |
| 显示 | [`rg_display.c/.h`](../../components/retro-go/rg_display.c) | 显示刷新、旋转、缩放和背光 |
| Surface | [`rg_surface.c/.h`](../../components/retro-go/rg_surface.c) | 像素缓冲和绘图表面 |
| 输入 | [`rg_input.c/.h`](../../components/retro-go/rg_input.c) | GPIO 按键、电池 ADC 和逻辑按键 |
| 音频 | [`rg_audio.c/.h`](../../components/retro-go/rg_audio.c) | 音频设备选择、音量和提交队列 |
| GUI | [`rg_gui.c/.h`](../../components/retro-go/rg_gui.c) | 菜单、对话框、选项和存档槽 |
| 存储 | [`rg_storage.c/.h`](../../components/retro-go/rg_storage.c) | SD 卡、FATFS、文件和目录 |

| 网络 | [`rg_network.c/.h`](../../components/retro-go/rg_network.c) | Wi-Fi、HTTP 和更新支持 |

## 应用连接方式

应用启动时调用 `rg_system_init()`，得到统一的 `rg_app_t`。应用将自己的显示、输入、存档和事件回调放入 `rg_handlers_t`，再进入专用主循环。

应用切换时，`rg_system_switch_app()` 保存目标分区、应用名、ROM 路径和启动标志，随后重启 ESP32。应用退出时使用 `rg_system_exit()` 返回 launcher。

## 依赖边界

公共运行时调用：

- ESP-IDF 驱动和系统组件
- [驱动层](../驱动层/驱动层.md)
- [板级适配层](../板级适配层/板级适配层.md)

公共运行时不应该包含某个特定模拟器的游戏逻辑。模拟器专用代码应留在应用适配层或对应 `components/` 中。

## 修改入口

- 修改跨应用行为：优先查看对应 `rg_*.c/.h`。
- 修改统一游戏菜单和存档槽：查看 `rg_gui.c`。
- 修改应用切换和启动参数：查看 `rg_system.c`。
- 修改具体硬件通信：转到 [驱动层](../驱动层/驱动层.md)。

## 知识点整理

### 系统生命周期

- `rg_system_init()`：建立应用运行环境，读取启动参数。
- `rg_system_reinit()`：应用内部切换模拟器时重新配置运行时。
- `rg_system_switch_app()`：保存分区、应用名、ROM 路径和启动标志。
- `rg_system_exit()`：退出当前应用并返回 launcher。
- `rg_system_tick()`：更新系统节拍和负载统计。

### 统一应用接口

应用通过 `rg_app_t` 获取当前应用状态，通过 `rg_handlers_t` 提供自己的事件处理器：

- 重绘事件
- 系统关机和睡眠事件
- 游戏菜单和选项
- 存档、恢复和重置
- 截图

### 公共数据流

```text
应用适配层
	|
	+--> rg_input_read_gamepad()
	+--> rg_surface_create() / rg_display_submit()
	+--> rg_audio_submit()
	+--> rg_storage_read_file() / rg_storage_write_file()
	+--> rg_gui_game_menu()
	|
	v
驱动层和板级配置层
```

### 设计边界

- 跨应用都需要的能力放在公共运行时。
- 某个模拟器专用的规则、回调和资源加载留在应用适配层。
- 具体 GPIO、SPI、I2S、ADC 和 RMT 操作留在驱动层。
- 目标硬件差异通过板级配置宏注入，不在公共代码中硬编码。
