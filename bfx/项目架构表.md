# 项目架构表

[返回知识点清单](知识点清单.md) | [应用模块索引](应用模块索引.md) | [硬件模块索引](驱动层/硬件模块索引.md)

## 1. 架构总览

本项目是面向 ESP32-S3 的 Retro-Go 分支，采用“一个公共运行时组件 + 多个独立 ESP-IDF 应用”的结构。各应用单独编译成一个应用镜像，并以独立分区安装到设备中。

```text
用户
  |
  v
launcher（启动器、ROM/电子书浏览、设置）
  |  保存目标分区、应用名和 ROM 路径
  |  rg_system_switch_app()
  v
ESP32-S3 重启并切换应用分区
  |
  +--> retro-core（NES/SNES/GB/GBC/PCE/SMS/G&W/Lynx）
  +--> gwenesis（Mega Drive / Genesis）
  +--> prboom-go（DOOM / Doom II）
  +--> fmsx（MSX）
  +--> txt-reader（TXT 电子书）

所有应用
  |
  v
components/retro-go（显示、输入、音频、存储、GUI、系统、电源等公共能力）
  |
  v
ESP-IDF + ESP32-S3 + t320-s3 板级配置
```

关键边界：应用之间通常不是函数调用关系，而是通过 ESP32 应用分区、启动参数和重启机制切换。应用内部才通过 C 函数调用公共 `retro-go` 组件。

## 2. 分层架构表

| 层级 | 目录或实现 | 主要职责 | 依赖方向 |
|---|---|---|---|
| [用户交互层](用户交互层/用户交互层.md) | `launcher/main`、各应用 `main` | 菜单、ROM/书籍选择、模拟器或阅读器主循环 | 调用公共运行时 |
| [应用适配层](应用适配层/应用适配层.md) | `retro-core`、`gwenesis`、`prboom-go`、`fmsx`、`txt-reader` | 解析启动参数，加载资源，驱动对应模拟器或阅读器 | 调用公共运行时和专用组件 |
| [公共运行时层](公共运行时层/公共运行时层.md) | `components/retro-go` | 系统生命周期、显示、Surface、输入、音频、GUI、存储、设置、网络和本地化 | 调用 ESP-IDF 与板级配置 |
| [驱动层](驱动层/驱动层.md) | `components/retro-go/drivers`、`rg_*.c` | SPI 显示、I2S 音频、GPIO 按键、ADC 电池、WS2812 等硬件访问 | 调用 ESP-IDF 驱动 |
| [板级适配层](板级适配层/板级适配层.md) | `components/retro-go/targets/t320-s3` | GPIO、屏幕参数、音频参数、芯片目标、SDK 配置和镜像环境 | 被公共运行时读取 |
| [平台层](平台层/平台层.md) | ESP-IDF 5.5.5、ESP32-S3 | FreeRTOS、分区、OTA、FATFS、NVS、SPI、ADC、I2S 等基础能力 | 提供底层服务 |

## 3. 独立应用表

| 应用工程 | 入口目录 | 顶层 CMake 组件 | 主要功能 | 网络 | 镜像分区大小 |
|---|---|---|---|---|---:|
| `launcher` | `launcher/main` | `main`、`retro-go`、`wifi`、`esp_http_server` | 启动器、ROM/书籍浏览、设置、更新、WebUI | 开启 | 1.5 MiB |
| `retro-core` | `retro-core/main` | `main`、`retro-go`、`nofrendo`、`gnuboy`、`pce-go`、`gw-emulator`、`handy`、`smsplus`、`snes9x` | NES、SNES、GB、GBC、PCE、SMS、G&W、Lynx | 关闭 | 1 MiB |
| `prboom-go` | `prboom-go/main` | `main`、`retro-go`、`prboom` | DOOM / Doom II | 关闭 | 768 KiB |
| `gwenesis` | `gwenesis/main` | `main`、`retro-go`、`gwenesis` | Sega Mega Drive / Genesis | 关闭 | 1 MiB |
| `fmsx` | `fmsx/main` | `main`、`retro-go`、`fmsx` | MSX、ROM 和 DSK 镜像 | 关闭 | 576 KiB |
| `txt-reader` | `txt-reader/main` | `main`、`retro-go` | TXT 电子书、UTF-8/GBK 阅读 | 关闭 | 5 MiB |

分区大小和应用顺序由 `rg_tool.py` 中的 `PROJECT_APPS` 定义。实际设备是否显示某个应用，还要由启动器检查同名应用分区是否存在。

## 4. 公共运行时模块表

| 模块 | 文件 | 架构职责 |
|---|---|---|
| 系统与应用切换 | `rg_system.c/.h` | 初始化运行时、保存启动参数、设置 OTA 启动分区、重启、返回启动器 |
| 显示与绘图 | `rg_display.c/.h`、`rg_surface.c/.h` | 显示初始化、刷新、旋转、缩放、Surface 和帧缓冲操作 |
| 输入 | `rg_input.c/.h` | GPIO 按键读取、逻辑按键映射、BOOT/恢复相关输入、电池 ADC 读取 |
| 音频 | `rg_audio.c/.h`、`drivers/audio` | 音频设备选择、音量、滤波和 I2S 输出 |
| GUI | `rg_gui.c/.h` | 菜单、对话框、系统选项、存档槽和通用界面行为 |
| 存储 | `rg_storage.c/.h` | SD 卡、FATFS、ROM、存档、资源和文件操作 |
| 设置与本地化 | `rg_settings.c/.h`、`rg_localization.c/.h`、`translations.h` | NVS 设置、语言文案和翻译资源 |
| 网络 | `rg_network.c/.h`、ESP-IDF Wi-Fi/HTTP 组件 | 网络连接、更新和 WebUI 支持，主要由启动器使用 |
| 板级驱动 | `drivers/display`、`drivers/led`、`targets/t320-s3` | ST7789/显示控制、WS2812、GPIO 和目标参数 |

## 5. 应用切换数据流

| 步骤 | 执行位置 | 输入/输出 |
|---:|---|---|
| 1 | `launcher/main/applications.c` | 扫描 SD 卡并把文件映射到应用短名称和目标分区 |
| 2 | `application_start()` | 生成目标分区、应用名、ROM 路径和启动标志 |
| 3 | `rg_system_switch_app()` | 保存启动配置，并调用 ESP-IDF OTA 接口选择目标应用分区 |
| 4 | `rg_system_restart()` | 重启 ESP32-S3 |
| 5 | 目标应用 `main` | 调用 `rg_system_init()`，读取应用名和 ROM 路径 |
| 6 | 模拟器/阅读器主循环 | 从 SD 卡加载资源，使用公共显示、输入、音频和存档接口运行 |
| 7 | 应用退出 | 调用 `rg_system_exit()`，切回 `launcher` 分区 |

ROM 到应用的映射关系：

| ROM/资源类型 | 目标应用 | 目录示例 |
|---|---|---|
| NES、SNES、GB、GBC、PCE、SMS、G&W、Lynx | `retro-core` | `roms/nes`、`roms/snes`、`roms/gb` 等 |
| Mega Drive / Genesis | `gwenesis` | `roms/md` |
| DOOM | `prboom-go` | `roms/doom` |
| MSX | `fmsx` | `roms/msx` |
| TXT 电子书 | `txt-reader` | `roms/txt` |

## 6. 硬件资源表（t320-s3）

| 硬件资源 | 公共接口/驱动 | 板级配置 |
|---|---|---|
| 3.2 寸 TFT（320x240） | `rg_display.c`、`drivers/display` | SPI、背光、DC、RST、CS、MOSI、CLK |
| SD 卡 | `rg_storage.c` | SDSPI、FATFS、CMD、CLK、DATA、CD |
| I2S 扬声器 | `rg_audio.c`、`drivers/audio/i2s.c` | DOUT、BCLK、LRCK |
| GPIO 按键 | `rg_input.c` | BOOT、MENU、OPTION、SELECT、START、A/B、方向键 |
| 电池检测 | `rg_input.c` | ADC 电池采样 GPIO |
| WS2812 状态灯 | `drivers/led/ws2812.c` | RMT、状态灯 GPIO |
| 麦克风预留 | 当前未被 Retro-Go 使用 | MIC_WS、MIC_SCK、MIC_DIN |

具体 GPIO 和电气连接以 `components/retro-go/targets/t320-s3/config.h` 及硬件文档为准。

## 7. 构建与发布链路

| 阶段 | 工具/位置 | 作用 |
|---|---|---|
| 目标选择 | `--target=t320-s3`、`targets/t320-s3/env.py` | 设置 ESP32-S3、项目名、镜像格式和目标参数 |
| 单应用配置 | 各应用 `CMakeLists.txt` | 选择公共组件、模拟器组件和网络能力 |
| 编译 | `idf.py app` | 分别生成 `app/build/<app>.bin` |
| 镜像打包 | `tools/mkfw.py`，由 `rg_tool.py` 调用 | 按应用顺序、分区类型和大小合成整机镜像 |
| 烧录 | `idf.py` / `esptool.py` / `parttool.py` | 可烧录完整镜像，或写入已有设备的指定应用分区 |
| 运行时存储 | SD 卡和应用分区 | SD 卡保存 ROM、书籍、存档和资源；应用分区保存可执行镜像 |

常用命令：

```bat
python rg_tool.py --target=t320-s3 build-img
python rg_tool.py --target=t320-s3 --port=COM3 install
python rg_tool.py --target=t320-s3 release
```

## 8. 关键设计约束

- `components/retro-go` 是所有应用共享的公共能力边界，应用目录一般不直接操作 GPIO。
- 启动器只能显示设备上实际存在的应用分区，因此注册的应用数量可能多于当前构建的应用数量。
- `rg_tool.py` 中的应用大小是打包约束；增加字体、资源或功能时必须检查对应分区空间。
- 构建时生成的根目录 `partitions.csv` 只是 ESP-IDF 构建占位文件，实际整机应用布局由镜像打包流程生成。
- 当前 `rg_tool.py` 默认目标仍是 `odroid-go`，构建本项目必须显式指定 `--target=t320-s3`。
- `RG_ENABLE_NETWORKING` 由各应用顶层 `CMakeLists.txt` 控制；启动器开启网络，其余应用当前关闭网络。
